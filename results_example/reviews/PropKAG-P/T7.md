# 代码大模型与软件工程智能体：从代码生成到仓库级任务的研究进展

代码大模型研究已从孤立代码片段走向仓库级软件工程任务，多智能体协作与检索增强成为新范式（P003, P001, P024）。多篇综述从生成、修复和理解等不同视角系统梳理了领域进展，形成互补的证据版图（P005, P021, P007）。不同研究采用异构基准与任务设定，其数值结果多具局部性，跨场景迁移需谨慎（P016, P019）。

多智能体软件工程系统通过任务分解和角色协调提升复杂仓库级任务的执行能力（P001, P028, P006）。仓库级智能体采用代码图、知识图谱、插件化结构等机制增强对全局代码库的上下文理解（P003, P010, P012）。部分新架构将自然语言指令编译为依赖图或采用冯·诺依曼式存储组织，以突破上下文窗口限制并实现大规模生成（P008, P026）。在程序定位与修复环节，引入定位-建议-修复流程、更优检索和外部工具可改善智能体效果（P006, P010, P011）。评测显示，将基准扩展至更多仓库后智能体成功率显著下降，揭示模型在整合仓库全局信息上存在主要瓶颈（P016, P014）。效率方面，推测解码可加速代码生成与修复，而效率批判提示能在无执行下显著降低资源开销（P022, P023）。代码审查场景中，检索增强与上下文增强框架能辅助生成更有用的审查意见（P027）。

多篇综述从不同维度归纳了大模型驱动的代码生成研究，包括智能体形态、任务分类与深度学习技术路线（P004, P005, P007）。检索增强生成在软件工程中的系统综述显示，RAG 已广泛用于代码生成、测试生成与程序修复等多个下游任务（P024）。虽然 GPT-4 在 LeetCode 等任务接近人类水平，但大规模理解评测仍显示现有代码模型存在明显不足（P005, P025）。在自动程序修复方面，综述确认 LLM 显著弥补了传统方法在代码理解与补丁生成上的不足，同时指出泛化挑战（P013, P019, P021）。具体修复方法包括双记忆系统增强仓库级修复、以及用探索-利用权衡优化迭代修复的调用次数（P015, P030）。这些综述与实证研究互为补充，既提供系统分类，又给出可执行策略（P020, P013）。

总体而言，该领域已形成方法、评估与训练并进的发展态势，并在基准扩展、效率优化和自对弈训练等方向取得进展（P029, P025, P015）。当前证据多来自各自独立设定的实验，不同综述和实证结果的直接可比性有限，阻碍了稳健结论的形成（P020, P021）。未来发展需解决上下文整合、跨仓库泛化、多智能体协作效率以及更统一、可复现的评测协议等开放问题（P014, P023, P019）。
